MLStoreDB — Manual

BD JSON + Grafos · embebida, cifrada, con wire protocol Mongo

01 · Conexión

Base de datos en memoria

store := db.New()          // RAM, sin archivo
defer store.Close()

Base de datos en archivo cifrado

store, err := db.OpenWithLock("datos.mlstore", db.Options{
    MasterKey: []byte("mi-clave-maestra-de-32-bytes!!"), // KEK
    MachineID: "mi-equipo",                               // opcional
})
defer store.Close()
  • Open abre/crea el archivo sin lock de proceso.
  • OpenWithLock además toma un lock exclusivo: dos procesos no pueden abrir la misma BD.
  • El archivo queda cifrado con AES-256-GCM (nunca hay JSON en claro).

Opciones útiles de Options

CampoQué hace
MasterKey []byteClave maestra (KEK). Requerida para archivos.
SyncOnWrite boolFlush síncrono tras cada mutación (durabilidad).
AutoFlush time.DurationPeríodo del flush automático (default 2s).
CacheBytes int64Presupuesto del page cache (0=256MB, <0=ilimitado).
FindWorkers intGoroutines para Find paralelo (0=GOMAXPROCS).
SessionTTL time.DurationVida de las sesiones RBAC (0=24h, <0=nunca).

Usuarios, roles y sesiones (RBAC)

// 1) rol con permisos
store.CreateRole("editor", []db.Permission{
    {Collection: "orders", Read: true, Write: true},
    {Collection: "audit",  Read: true},   // solo lectura
})
store.CreateRole("admin", []db.Permission{
    {Collection: "*", Read: true, Write: true},  // comodín
})
// 2) usuario (activa RBAC en el primero)
store.CreateUser("ana", "secreto", []string{"editor"})
// 3) autenticar → sesión
sess, err := store.Authenticate("ana", "secreto")
docs, _ := sess.Find("orders", db.Document{"status": "PAID"}, nil)
Sin usuarios la API cruda funciona sin restricciones; con ≥1 usuario la API cruda devuelve ErrUnauthorized y hay que usar la Session.

Desde clientes Mongo

go run ./tools/mls-server -addr 127.0.0.1:27017 -path datos.mlstore \
    -key "mi-clave-maestra-de-32-bytes!!" -db midb

Conéctate con mongodb://127.0.0.1:27017 (Navicat / Compass / mongosh). Detalle en la pestaña 09.

01 · Connection

In-memory database

store := db.New()          // RAM, no file
defer store.Close()

Encrypted file database

store, err := db.OpenWithLock("data.mlstore", db.Options{
    MasterKey: []byte("my-32-bytes-long-master-key!!"), // KEK
    MachineID: "my-machine",                            // optional
})
defer store.Close()
  • Open opens/creates the file without a process lock.
  • OpenWithLock also takes an exclusive lock: two processes cannot open the same DB.
  • The file is AES-256-GCM encrypted (no plaintext JSON ever hits disk).

Useful Options fields

FieldWhat it does
MasterKey []byteMaster key (KEK). Required for files.
SyncOnWrite boolSynchronous flush after every mutation (durability).
AutoFlush time.DurationAuto-flush ticker period (default 2s).
CacheBytes int64Page cache budget (0=256MB, <0=unlimited).
FindWorkers intGoroutines for parallel Find (0=GOMAXPROCS).
SessionTTL time.DurationRBAC session lifetime (0=24h, <0=never).

Users, roles and sessions (RBAC)

// 1) role with permissions
store.CreateRole("editor", []db.Permission{
    {Collection: "orders", Read: true, Write: true},
    {Collection: "audit",  Read: true},   // read-only
})
store.CreateRole("admin", []db.Permission{
    {Collection: "*", Read: true, Write: true},  // wildcard
})
// 2) user (RBAC activates with the first one)
store.CreateUser("ana", "secret", []string{"editor"})
// 3) authenticate → session
sess, err := store.Authenticate("ana", "secret")
docs, _ := sess.Find("orders", db.Document{"status": "PAID"}, nil)
With no users the raw API works unrestricted; with ≥1 user the raw API returns ErrUnauthorized and you must use the Session.

From Mongo clients

go run ./tools/mls-server -addr 127.0.0.1:27017 -path data.mlstore \
    -key "my-32-bytes-long-master-key!!" -db mydb

Connect with mongodb://127.0.0.1:27017 (Navicat / Compass / mongosh). Details in tab 09.

02 · Insertar

Insert básico

err := store.Insert("clientes", db.Document{
    "_id":   "c1",
    "nombre": "Ana",
    "ciudad": "Lima",
})
  • La colección se crea sola la primera vez que insertas.
  • _id debe ser string. Si lo omites, se genera un ULID automático.

Documentos anidados y arrays

store.Insert("orders", db.Document{
    "_id": "o100", "total": 250.0, "buyer_id": "c1",
    "items": []any{
        db.Document{"sku": "A1", "qty": 2, "precio": 100.0},
        db.Document{"sku": "B2", "qty": 1, "precio": 50.0},
    },
    "shipping": db.Document{
        "mode": "air",
        "addr": db.Document{"city": "Lima", "zip": "15001"},
    },
})

Upsert (crear o reemplazar por _id)

store.Upsert("clientes", "c1", db.Document{
    "_id": "c1", "nombre": "Ana", "nivel": "gold",
})

Índice unique + duplicados

store.EnsureIndex("clientes", []string{"email"}, true) // unique
err := store.Insert("clientes", db.Document{"_id": "c2", "email": "ana@x.com"})
// err == db.ErrDuplicate si ya existe

Desde mongosh / Navicat

db.clientes.insertOne({ _id: "c1", nombre: "Ana", ciudad: "Lima" })
db.orders.insertMany([
  { _id: "o1", total: 100, buyer_id: "c1" },
  { _id: "o2", total: 250, buyer_id: "c1" }
])
Por el wire, un _id ObjectId o numérico se normaliza a string (hex del ObjectId).

Límites

  • Tamaño máximo por documento: 1 MB (db.ErrTooLarge).
  • Colecciones de sistema (_users, _roles, _triggers) rechazan inserts directos.

03 · Consultar (SELECT)

Por _id

doc, err := store.Get("clientes", "c1")   // ErrNotFound si no existe

Find con filtro

docs, err := store.Find("orders",
    db.Document{"status": "PAID"},   // igualdad
    nil,
)

Operadores de comparación

db.Document{"total": db.Document{"$gte": 100}}   // >= 100
db.Document{"total": db.Document{"$gt": 100}}    // >  100
db.Document{"total": db.Document{"$lt": 500}}    // <  500
db.Document{"total": db.Document{"$lte": 500}}   // <= 500
db.Document{"total": db.Document{"$ne": 0}}      // != 0 (missing → true)
db.Document{"st": db.Document{"$in": []any{"A", "C"}}}
db.Document{"st": db.Document{"$nin": []any{"X"}}}

Regex, existencia y lógicos

db.Document{"tag": db.Document{"$regex": "^a", "$options": "i"}} // i=insensible
db.Document{"campo": db.Document{"$exists": true}}
db.Document{"campo": nil}                    // null o ausente

db.Document{"$and": []any{
    db.Document{"status": "PAID"},
    db.Document{"total": db.Document{"$gte": 100}},
}}
db.Document{"$or":  []any{ ... }}
db.Document{"$nor": []any{ ... }}
db.Document{"$not": db.Document{"status": "PAID"}}

Campos anidados (paths punteados)

db.Document{"shipping.mode": "air"}
db.Document{"payload.shipping.mode": db.Document{"$ne": "sea"}}

Sort, Limit, Skip, Projection

docs, err := store.Find("orders",
    db.Document{"total": db.Document{"$gte": 100}},
    &db.FindOptions{
        Sort:       map[string]int{"total": -1},  // 1 asc, -1 desc
        Limit:      10,
        Skip:       20,                           // paginación
        Projection: []string{"total", "buyer_id"}, // _id siempre incluido
    },
)

Count e índices

n, _ := store.Count("orders", db.Document{"status": "PAID"})

store.EnsureIndex("orders", []string{"status"}, false)         // simple
store.EnsureIndex("orders", []string{"buyer_id", "status"}, false) // compuesto
store.EnsureIndex("orders", []string{"order_id"}, true)        // unique

Los filtros de igualdad/$in/rango usan el índice automáticamente si cubre el campo.

Desde mongosh / Navicat

db.orders.find({ total: { $gte: 100 } }).sort({ total: -1 }).limit(10).skip(20)
db.orders.find({ status: "PAID" }, { total: 1, buyer_id: 1 })
db.orders.countDocuments({ status: "PAID" })
db.orders.findOne({ _id: "o100" })
Soportados: $eq $ne $gt $gte $lt $lte $in $nin $regex $options $exists $and $or $not $nor. No soportados: $elemMatch $size $type $mod $all $where $expr.

04 · Actualizar (UPDATE)

Update con patch (merge shallow)

err := store.Update("clientes", "c1", db.Document{
    "nivel": "gold",   // se añade/actualiza; el resto queda intacto
})

Copy-on-write: si la validación falla (tamaño, índice unique), el documento vivo no queda a medias.

UpdateFields: patch + borrar campos

err := store.UpdateFields("clientes", "c1",
    db.Document{"nivel": "gold"}, // set
    []string{"temp", "cache"},    // unset (borrar)
)

Actualizar campos anidados

doc, _ := store.Get("orders", "o100")
ship := doc["shipping"].(db.Document)
ship["mode"] = "sea"
store.Update("orders", "o100", db.Document{"shipping": ship})

Desde mongosh / Navicat (operadores del wire)

db.clientes.updateOne(
  { _id: "c1" },
  { $set: { nivel: "gold", "perfil.vip": true } }   // paths punteados OK
)
db.clientes.updateOne({ _id: "c1" }, { $unset: { temp: "" } })
db.orders.updateMany({ status: "PAID" }, { $inc: { intentos: 1 } })
db.orders.updateOne({ _id: "o100" }, { $push: { items: { sku: "C3", qty: 1 } } })
db.orders.updateOne({ _id: "o100" }, { $pull: { items: { sku: "B2" } } })

// reemplazo completo (conserva _id)
db.clientes.replaceOne({ _id: "c1" }, { nombre: "Ana", nivel: "gold" })

// upsert: inserta si no hay match
db.counters.updateOne({ coll: "orders" }, { $inc: { n: 1 } }, { upsert: true })

// devuelve el documento modificado
db.orders.findAndModify({
  query: { _id: "o100" },
  update: { $set: { locked: true } },
  new: true
})
Operadores del wire: $set $unset $inc $mul $min $max $rename $push $addToSet $pop $pull $pullAll $currentDate $setOnInsert + reemplazo. Pipelines de update: no soportados.

05 · Eliminar (DELETE)

Por _id

err := store.Delete("clientes", "c1")   // ErrNotFound si no existe

Por filtro (find + delete)

docs, _ := store.Find("orders", db.Document{"status": "CANCELLED"}, nil)
for _, d := range docs {
    _ = store.Delete("orders", d["_id"].(string))
}

Eliminar campo (no el documento)

store.UpdateFields("orders", "o100", nil, []string{"temp"})

Eliminar colección completa

store.DropCollection("orders")   // borra docs + índices

Cada documento pasa por el path de delete normal (registros DEL, hooks, caché) y el scan del archivo está protegido para que la colección no resucite al reabrir.

Desde mongosh / Navicat

db.clientes.deleteOne({ _id: "c1" })
db.orders.deleteMany({ status: "CANCELLED" })   // todos los matches
db.orders.drop()
Los hooks before_delete / after_delete (y triggers sobre ellos) se disparan en cada borrado, igual que desde Go.

06 · Joins: combinar colecciones y armar JSON anidado

No hay JOIN de SQL, pero hay cuatro patrones para relacionar colecciones.

// datos de ejemplo
store.Insert("customers", db.Document{"_id": "c1", "nombre": "Ana", "city": "Lima"})
store.Insert("customers", db.Document{"_id": "c2", "nombre": "Bo",  "city": "Bogotá"})
store.Insert("orders", db.Document{"_id": "o1", "total": 100, "buyer_id": "c1"})
store.Insert("orders", db.Document{"_id": "o2", "total": 250, "buyer_id": "c1"})
store.Insert("orders", db.Document{"_id": "o3", "total":  80, "buyer_id": "c2"})

Patrón A — Embeber un documento (1 a 1)

order, _ := store.Get("orders", "o1")
cust, _  := store.Get("customers", order["buyer_id"].(string))
order["customer"] = cust   // ← JSON anidado

// order = { _id: "o1", total: 100, buyer_id: "c1",
//           customer: { _id: "c1", "nombre": "Ana", city: "Lima" } }

Patrón B — Batch con $in (N documentos, 2 queries)

El patrón clásico para listados: 1 find de orders + 1 find de customers, sin N+1:

orders, _ := store.Find("orders", nil, nil)

idSet := map[string]bool{}          // 1) ids únicos de buyers
var ids []any
for _, o := range orders {
    id := o["buyer_id"].(string)
    if !idSet[id] { idSet[id] = true; ids = append(ids, id) }
}
customers, _ := store.Find("customers",   // 2) todos de golpe
    db.Document{"_id": db.Document{"$in": ids}}, nil)
byID := map[string]db.Document{}
for _, c := range customers { byID[c["_id"].(string)] = c }

for _, o := range orders {             // 3) anidar
    o["customer"] = byID[o["buyer_id"].(string)]
}

Patrón C — $lookup con aggregate (wire / mongosh / Compass)

db.orders.aggregate([
  { $match: { total: { $gte: 100 } } },
  { $lookup: {
      from:         "customers",
      localField:   "buyer_id",
      foreignField: "_id",
      as:           "customer"
  }},
  { $unwind: "$customer" },
  { $sort: { total: -1 } }
])

Resultado: un doc por order con el customer anidado:

{ "_id": "o2", "total": 250, "buyer_id": "c1",
  "customer": { "_id": "c1", "nombre": "Ana", "city": "Lima" } }

Patrón D — Relación como grafo (edges)

store.AddEdge("compro", "c1", "o1", db.Document{"canal": "web"})
store.AddEdge("compro", "c1", "o2", db.Document{"canal": "app"})

orderIDs, _ := store.Neighbors("compro", "c1", db.Outgoing) // orders de Ana

// las aristas son documentos consultables:
store.Find("edges.compro", db.Document{"canal": "web"}, nil)

¿Qué patrón usar?

NecesitasPatrón
Un doc + su padre (detalle)A (Get + Get)
Listado con padre embebidoB ($in batch)
Consulta desde el cliente GUIC ($lookup aggregate)
Relación con propiedades / recorridosD (edges/grafo)

06 · Joins: combining collections into nested JSON

There is no SQL JOIN, but there are four patterns to relate collections.

// sample data
store.Insert("customers", db.Document{"_id": "c1", "nombre": "Ana", "city": "Lima"})
store.Insert("customers", db.Document{"_id": "c2", "nombre": "Bo",  "city": "Bogotá"})
store.Insert("orders", db.Document{"_id": "o1", "total": 100, "buyer_id": "c1"})
store.Insert("orders", db.Document{"_id": "o2", "total": 250, "buyer_id": "c1"})
store.Insert("orders", db.Document{"_id": "o3", "total":  80, "buyer_id": "c2"})

Pattern A — Embed one document (1-to-1)

order, _ := store.Get("orders", "o1")
cust, _  := store.Get("customers", order["buyer_id"].(string))
order["customer"] = cust   // ← nested JSON

// order = { _id: "o1", total: 100, buyer_id: "c1",
//           customer: { _id": "c1", "nombre": "Ana", city: "Lima" } }

Pattern B — Batch with $in (N documents, 2 queries)

The classic pattern for listings: 1 find on orders + 1 find on customers, no N+1:

orders, _ := store.Find("orders", nil, nil)

idSet := map[string]bool{}          // 1) unique buyer ids
var ids []any
for _, o := range orders {
    id := o["buyer_id"].(string)
    if !idSet[id] { idSet[id] = true; ids = append(ids, id) }
}
customers, _ := store.Find("customers",   // 2) all at once
    db.Document{"_id": db.Document{"$in": ids}}, nil)
byID := map[string]db.Document{}
for _, c := range customers { byID[c["_id"].(string)] = c }

for _, o := range orders {             // 3) nest
    o["customer"] = byID[o["buyer_id"].(string)]
}

Pattern C — $lookup with aggregate (wire / mongosh / Compass)

db.orders.aggregate([
  { $match: { total: { $gte: 100 } } },
  { $lookup: {
      from:         "customers",
      localField:   "buyer_id",
      foreignField: "_id",
      as:           "customer"
  }},
  { $unwind: "$customer" },
  { $sort: { total: -1 } }
])

Result: one doc per order with the customer nested:

{ "_id": "o2", "total": 250, "buyer_id": "c1",
  "customer": { "_id": "c1", "nombre": "Ana", "city": "Lima" } }

Pattern D — Relationship as a graph (edges)

store.AddEdge("bought", "c1", "o1", db.Document{"channel": "web"})
store.AddEdge("bought", "c1", "o2", db.Document{"channel": "app"})

orderIDs, _ := store.Neighbors("bought", "c1", db.Outgoing) // Ana's orders

// edges are queryable documents:
store.Find("edges.bought", db.Document{"channel": "web"}, nil)

Which pattern?

You needPattern
One doc + its parent (detail view)A (Get + Get)
Listing with parent embeddedB ($in batch)
Query from a GUI clientC ($lookup aggregate)
Relationship with properties / traversalsD (edges/graph)

07 · Triggers y Hooks

Dos mecanismos: hooks Go (código en tu proceso) y triggers JSON (reglas persistidas en la BD).

Eventos: before_insert · after_insert · before_update · after_update · before_delete · after_delete · before_upsert · after_upsert

Veto con before_* (la mutación no ocurre)

store.On("before_insert", "orders", func(h *db.HookContext) error {
    if total, _ := h.Doc["total"].(float64); total < 0 {
        return errors.New("total no puede ser negativo") // = veto
    }
    return nil
})

Mutar el documento antes de insertar

store.On("before_insert", "orders", func(h *db.HookContext) error {
    h.Doc["creado_en"] = time.Now().Format(time.RFC3339)
    return nil
})

Auditoría después de insertar

store.On("after_insert", "orders", func(h *db.HookContext) error {
    return h.Insert("audit", db.Document{"ref": h.ID, "ev": h.Event})
})

Asíncrono (cola FIFO, no bloquea)

store.OnAsync("after_insert", "orders", func(h *db.HookContext) error {
    return h.Update("counters", "orders", db.Document{"last": h.ID})
})
store.WaitAsyncHooks()   // barrera para tests/ops

HookContext

CampoContenido
h.Event"after_insert", …
h.Collectioncolección afectada
h.ID_id del documento
h.Docdoc nuevo / patch (preview merged en before_update)
h.Olddoc previo (update/delete); nil en insert

Métodos: h.Get / h.Find / h.Count / h.Insert / h.Upsert / h.Update / h.Delete — las mutaciones anidadas deben ir por h.* (frame de profundidad/ciclos).

Triggers JSON — CreateTrigger

store.CreateTrigger(db.Trigger{
    ID:         "audit_paid",
    Event:      "after_insert",
    Collection: "orders",
    Filter:     map[string]any{"status": "PAID"},  // solo si matchea
    Actions: []db.TriggerAction{
        {Type: "insert", Collection: "audit",
         Doc: map[string]any{
             "ref":  map[string]any{"$get": "_id"},   // template
             "note": "orden pagada",
         }},
    },
})

Templates y más ejemplos

// {"$get": "_id"}       → del doc del evento
// {"$get": "old.total"} → del doc previo

    Event: "before_insert", Collection: "orders",
    Actions: []db.TriggerAction{

    },
})

    },

store.DeleteTrigger("cnt_orders")
Protecciones: profundidad máx 8 (ErrHookDepth), ciclos (ErrHookCycle), cola async acotada (1024). Los triggers se re-registran solos al reabrir la BD.

08 · Grafos

Crear y borrar aristas

// AddEdge(tipo, desde, hasta, props) → _id de la arista (ULID)
id, _ := store.AddEdge("knows", "ana", "bob", db.Document{"desde": 2024})
store.AddEdge("knows", "bob", "carla", nil)
store.AddEdge("knows", "ana", "carla", db.Document{"desde": 2020})

store.RemoveEdge("knows", id)   // por _id de arista

Cada arista es un documento en la colección edges.<tipo>, consultable con Find normal:

store.Find("edges.knows", db.Document{"desde": db.Document{"$gte": 2020}}, nil)

Vecinos

amigos, _ := store.Neighbors("knows", "ana", db.Outgoing) // ["bob", "carla"]
_, _     = store.Neighbors("knows", "bob",  db.Incoming)  // ["ana"]
todos, _ := store.Neighbors("knows", "ana", db.Both)      // unión dedupe

Recorrido BFS — Traverse

nodes, _ := store.Traverse(db.TraverseOptions{
    EdgeType:  "knows",
    Start:     "ana",
    Direction: db.Outgoing,  // default
    MaxDepth:  2,            // default 5, máx 32
    MinDepth:  1,            // excluir el inicio (depth 0)
    Limit:     100,          // default 10000, máx 100000
})
for _, n := range nodes {
    fmt.Println(n.Vertex, "a", n.Depth, "saltos")
}

Ruta más corta — ShortestPath

path, _ := store.ShortestPath("knows", "ana", "carla", 4)
// ["ana", "carla"]  (arista directa)

path, _ = store.ShortestPath("knows", "carla", "bob", 4)
// ["carla", "ana", "bob"]  (2 saltos) · nil si no hay ruta

Grafo + RBAC

sess, _ := store.Authenticate("ana", "secreto")
sess.AddEdge("knows", "ana", "dave", nil)
sess.Neighbors("knows", "ana", db.Outgoing)
sess.Traverse(db.TraverseOptions{EdgeType: "knows", Start: "ana"})
sess.ShortestPath("knows", "ana", "dave", 3)

Ejemplo: red de recomendación

// amigos de amigos (depth exactamente 2)
nodes, _ := store.Traverse(db.TraverseOptions{
    EdgeType: "knows", Start: "ana", MinDepth: 2, MaxDepth: 2,
})
for _, n := range nodes {
    if path, _ := store.ShortestPath("knows", "ana", n.Vertex, 3); path != nil {
        fmt.Printf("sugerencia %s ← %v\n", n.Vertex, path)
    }
}
Múltiples aristas entre el mismo par se deduplican; la caché CSR se invalida sola ante cualquier mutación de edges.*; tipos distintos son grafos independientes.

08 · Graphs

Creating and removing edges

// AddEdge(type, from, to, props) → edge _id (ULID)
id, _ := store.AddEdge("knows", "ana", "bob", db.Document{"since": 2024})
store.AddEdge("knows", "bob", "carla", nil)
store.AddEdge("knows", "ana", "carla", db.Document{"since": 2020})

store.RemoveEdge("knows", id)   // by edge _id

Each edge is a document in the edges.<type> collection, queryable with plain Find:

store.Find("edges.knows", db.Document{"since": db.Document{"$gte": 2020}}, nil)

Neighbors

friends, _ := store.Neighbors("knows", "ana", db.Outgoing) // ["bob", "carla"]
_, _      = store.Neighbors("knows", "bob",  db.Incoming)  // ["ana"]
all, _    := store.Neighbors("knows", "ana", db.Both)      // deduped union

BFS traversal — Traverse

nodes, _ := store.Traverse(db.TraverseOptions{
    EdgeType:  "knows",
    Start:     "ana",
    Direction: db.Outgoing,  // default
    MaxDepth:  2,            // default 5, max 32
    MinDepth:  1,            // exclude start (depth 0)
    Limit:     100,          // default 10000, max 100000
})
for _, n := range nodes {
    fmt.Println(n.Vertex, "at", n.Depth, "hops")
}

Shortest path — ShortestPath

path, _ := store.ShortestPath("knows", "ana", "carla", 4)
// ["ana", "carla"]  (direct edge)

path, _ = store.ShortestPath("knows", "carla", "bob", 4)
// ["carla", "ana", "bob"]  (2 hops) · nil when no path

Graph + RBAC

sess, _ := store.Authenticate("ana", "secret")
sess.AddEdge("knows", "ana", "dave", nil)
sess.Neighbors("knows", "ana", db.Outgoing)
sess.Traverse(db.TraverseOptions{EdgeType: "knows", Start: "ana"})
sess.ShortestPath("knows", "ana", "dave", 3)

Example: recommendation network

// friends of friends (exactly depth 2)
nodes, _ := store.Traverse(db.TraverseOptions{
    EdgeType: "knows", Start: "ana", MinDepth: 2, MaxDepth: 2,
})
for _, n := range nodes {
    if path, _ := store.ShortestPath("knows", "ana", n.Vertex, 3); path != nil {
        fmt.Printf("suggestion %s ← %v\n", n.Vertex, path)
    }
}
Multiple edges between the same pair are deduplicated; the CSR cache self-invalidates on any edges.* mutation; different types are independent graphs.

09 · Servidor Mongo-compatible

mls-server expone la BD por TCP hablando el wire protocol de MongoDB (subset OP_MSG + legado), para Navicat, Compass o mongosh sin escribir código.

Arrancar

# in-memory

go run ./tools/mls-server -addr 127.0.0.1:27017 \

# con SCRAM-SHA-256 (opcional)
go run ./tools/mls-server -addr 127.0.0.1:27017 -path datos.mlstore \

Particularidades del subset

  • _id: ObjectId y números se normalizan a string (hex del ObjectId).
  • Números: BSON int32/int64/double — el motor es numérico tipo JSON (5 y 5.0 son iguales al filtrar).
  • Sort multi-clave: se aplica en orden alfabético de campos.
  • Proyecciones punteadas y $elemMatch/$size/$type/$mod/$all/$expr no soportados.
  • Cursores con TTL de 10 min de inactividad; batch default 101 docs.
  • maxBsonObjectSize = 1 MB (límite real del motor).

db.clientes.aggregate([{ $group: { _id: "$city", n: { $sum: 1 } } }])
db.clientes.updateOne({ _id: "c1" }, { $set: { nivel: "gold" } })
db.clientes.deleteOne({ _id: "c1" })
